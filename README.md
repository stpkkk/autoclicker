# hh-autoapply

CLI-приложение на Node.js + TypeScript, которое помогает делать отклики на hh.ru
через браузер Playwright. Официальный API не используется.

Главные принципы:

- **только ручной вход** — приложение не спрашивает и не хранит логин/пароль;
- **капчу и антибот не обходим** — при проверке процесс встаёт на паузу и ждёт человека;
- **dry-run по умолчанию** — реальная отправка только с флагом `--send`;
- **человеческое поведение** — headed-браузер, случайные паузы, одна вкладка;
- **лучше остановиться, чем продолжать** — при лимитах, блокировках и серии ошибок.

## Требования

- Node.js 20+
- npm
- Windows, macOS или Linux

## Установка

```bash
npm install
npx playwright install chromium
```

Скопируйте пример конфига и заполните под себя:

```bash
# macOS / Linux
cp config.example.yaml config.yaml

# Windows PowerShell
Copy-Item config.example.yaml config.yaml
```

`config.yaml` и папка `.browser-profile/` добавлены в `.gitignore`: там личные
данные и сессия hh.ru.

## Первый вход

```bash
npm run login
```

Откроется обычное (headed) окно Chromium. Войдите на hh.ru вручную, включая
SMS/капчу, затем просто закройте окно. Сессия сохранится в `.browser-profile/`.

Проверка сессии и доступности резюме:

```bash
npm run check
```

Если сессия истекла — снова `npm run login`.

## Команды

Все команды запускаются из корня проекта.

```bash
npm run search                  # собрать вакансии и показать таблицу
npm run apply -- --limit 5      # DRY-RUN: ничего не отправляет
npm run apply -- --send --limit 5 --resume "Fullstack-разработчик"
npm run stats                   # сегодня / неделя / всё время
npm run doctor                  # проверить селекторы на реальных страницах
```

После `npm run build` можно запускать напрямую:

```bash
node dist/cli.js search
node dist/cli.js apply --send --limit 3
```

Или подключить как локальный бинарник:

```bash
npm link
hh-autoapply search
```

### `apply`

- По умолчанию работает в **dry-run**: открывает вакансию и форму отклика,
  проверяет фильтры, выбирает резюме, вставляет письмо, но **не нажимает кнопку
  отправки**.
- `--send` — реально отправляет отклики.
- `--limit N` — ограничить запуск. Итоговый лимит = `min(N, daily_limit, 100)`.
- `--resume "Название"` — выбрать резюме по названию, если hh показывает выбор.
- Если у вакансии есть вопросы/анкета работодателя — пропуск с причиной
  `needs_questions`.
- Если отклик уже был отправлен (по SQLite или по признаку на странице) — пропуск.
- Перед откликом описание **повторно** проверяется по стоп-словам уже на полной
  странице вакансии.

### `search`

Показывает название, компанию, зарплату, ссылку и причину пропуска. В текущей
выдаче hh.ru сниппеты описания часто отсутствуют, поэтому на этапе `search`
фильтр проверяет в основном название. Полное описание проверяется в `apply`.

### `doctor`

Проходит по реальным страницам: поиск → карточка вакансии → форма отклика.
Показывает, какие селекторы не найдены. Если форма отклика требует вход, честно
сообщает об этом. Запускайте после изменений на hh.ru или при странных пропусках.

## Конфиг

```yaml
search:
  queries:
    - 'Fullstack разработчик'
  area: 113 # 113 — Россия
  schedule: remote
  experience: between3And6
  salary: 250000 # опционально
  only_with_salary: false
  period: 7
  max_pages_per_query: 3

filters:
  stop_words: ['Java', 'PHP', '1С', 'C#', '.NET', 'Angular']
  must_have_any: ['React', 'Vue', 'TypeScript', 'Node.js', 'NestJS', 'Fullstack']
  skip_relocation: true
  allowed_cities: [] # можно указать ["Москва", "Санкт-Петербург"]

limits:
  daily_limit: 30 # жёсткий максимум в приложении — 100
  delay_ms_min: 15000
  delay_ms_max: 45000

cover_letter:
  templates:
    frontend: |
      ...текст с {{vacancy_name}} и {{employer_name}}...
    fullstack: |
      ...
```

Стоп-слова ищутся с учётом регистра и **границ слов**. Поэтому `Java` не
срабатывает на `JavaScript`, а `C#`, `.NET`, `1С`, `Senior+` обрабатываются
отдельно. Для кириллицы используется Unicode-граница, а не обычный `\b`.

Шаблон выбирается по названию вакансии: если есть `fullstack`/`full-stack`,
`Node.js`/`NodeJS` или `Nest.js`/`NestJS` — fullstack, иначе frontend.

Сопроводительное письмо вставляется только если на форме есть поле письма.
Пустые шаблоны запрещены валидацией zod.

## Архитектура

```text
src/
  cli.ts                 команды commander
  config/                YAML + zod
  browser/
    session.ts           persistent context, ручной вход
    humanize.ts          паузы и посимвольный ввод
    guards.ts            капча / лимит / блокировка / вход
  hh/
    selectors.ts         ВСЕ селекторы и тексты-индикаторы
    search.ts            сбор и парсинг выдачи
    vacancy.ts           карточка вакансии
    responseForm.ts      модалка/страница отклика, резюме, письмо
    applyFlow.ts         сценарий отклика и остановки
    doctor.ts            диагностика селекторов
  core/
    filter.ts            чистые фильтры
    template.ts          выбор и рендер шаблона
    limits.ts            лимиты
  db/                    SQLite и репозиторий
  utils/                 logger, sleep, retry
tests/                   vitest + HTML-фикстура
```

Почему так:

1. **Persistent context вместо логина через форму.** Пароль не хранится, cookie
   лежат в профиле браузера. Это и безопаснее, и позволяет человеку самому
   пройти SMS/капчу.
2. **Селекторы в одном файле.** hh.ru часто меняет DOM. Когда вёрстка поедет,
   править нужно одно место, а `doctor` покажет, что именно сломалось.
3. **Сначала `data-qa`, потом role/text.** CSS-классы на hh.ru генерируются и
   меняются, поэтому длинные цепочки вроде `div > div:nth-child(3)` не используем.
4. **Фильтр — чистая функция.** `filter.ts` не знает про Playwright и SQLite,
   поэтому его легко тестировать на строках и HTML-фикстурах.
5. **Повторная проверка описания.** В выдаче может не быть полного текста, поэтому
   `apply` перечитывает описание на странице вакансии перед откликом.
6. **Дедупликация на уровне БД.** `vacancy_id` — первичный ключ. Повторный запуск
   обновляет запись, но не создаёт дубликат и не понижает `sent`.
7. **`sent_at` в SQLite.** Добавлен поверх обязательных полей, чтобы корректно
   считать дневной лимит и статистику, даже если запись была создана в dry-run
   вчера, а отправлена сегодня.
8. **Остановки вместо ретраев отправки.** Повторное нажатие «Отправить» опаснее
   ошибки: можно получить дубль или лимит. Ретраи есть только у навигации.
9. **Подсказки не равны анкете.** `[data-qa^="vacancy-response-question"]` внутри
   `vacancy-response-suggest` — это блок «Задайте вопрос работодателю», а не
   обязательные вопросы. Реальная анкета определяется по отдельным `data-qa`,
   полям ввода и тексту вроде «ответьте на вопросы» / «заполните анкету».

## Что проверено на реальном hh.ru

Публичные страницы (поиск и карточка вакансии) проверялись через Playwright
12.11.2026. Подтверждены `data-qa` для карточек, названия, компании, адреса,
зарплаты (в новом макете зарплата иногда без `data-qa` — есть fallback-парсинг
текста) и кнопки отклика.

Форма отклика доступна только после входа. Её селекторы в `RESPONSE_SELECTORS`
помечены `TODO` и собраны по известным `data-qa` с fallback-вариантами. Селекторы
карточек резюме на странице `/applicant/resumes` тоже помечены `TODO`. После
`npm run login` запустите `npm run check` и `npm run doctor`, чтобы подтвердить их
на своём аккаунте. Если hh.ru обновит вёрстку, `doctor` покажет, какой селектор не
найден.

## Ограничения и риски

- Автоматизация откликов может нарушать правила hh.ru. Используйте на свой риск.
- Возможны ограничение или блокировка аккаунта. Начинайте с малых лимитов
  (3–5 откликов), не запускайте часто и не используйте несколько аккаунтов.
- Приложение не обходит капчу, антибот и проверки «вы не робот». Оно ждёт, пока
  вы решите проверку руками.
- Лимиты hh.ru могут быть скрытыми. Приложение останавливается, если видит
  сообщение о лимите, ограничении аккаунта или три ошибки подряд.
- Шаблоны писем — только заготовка. Персонализируйте их под вакансию, иначе
  отклики будут выглядеть шаблонными.
- hh.ru может изменить DOM в любой момент. В этом случае поможет `doctor`.
- Сопроводительное письмо не содержит телефон и email; контакты — Telegram и
  GitHub, как в шаблонах.

## Если что-то не работает

| Проблема                   | Что делать                                           |
| -------------------------- | ---------------------------------------------------- |
| `Не найден конфиг`         | Скопируйте `config.example.yaml` в `config.yaml`     |
| `Executable doesn't exist` | `npx playwright install chromium`                    |
| `Профиль занят`            | Закройте другое окно приложения/браузера             |
| `Сессия не активна`        | `npm run login`                                      |
| Селектор не найден         | `npm run doctor`                                     |
| Капча                      | Решите её в открытом окне, приложение продолжит само |
| Лимит/блокировка           | Приложение остановится. Не пытайтесь обойти          |
