# hh-autoapply

CLI-инструмент на Node.js + TypeScript, который помогает откликаться на вакансии hh.ru через браузер (Playwright). Официальный API не используется.

Это учебный проект: я делал его, чтобы на практике освоить Node.js, работу с нестабильным внешним сервисом, браузерную автоматизацию, валидацию конфигов и тестирование.

> ⚠️ **Важно.** Автоматизация действий на hh.ru может нарушать правила сервиса и привести к ограничению аккаунта. Проект не предназначен для массовой рассылки. Используйте на свой риск, с малыми лимитами и персонализированными письмами. Подробнее в разделе [Риски](#риски-и-ограничения).

## Возможности

- **Поиск** по нескольким запросам с пагинацией и удалением дублей между запросами.
- **Фильтрация** вакансий:
  - стоп-слова в названии (уровень, роль, чужой стек);
  - стоп-слова в разделе «Требования» с порогом срабатывания, чтобы упоминание стека проекта в описании не отсекало подходящие вакансии;
  - обязательные слова (`must_have_any`);
  - границы слов: `Java` не срабатывает на `JavaScript`, отдельно обрабатываются `C#`, `.NET`, `1С`.
- **Сопроводительные письма**: два шаблона (frontend и fullstack), выбор по названию вакансии, подстановка `{{vacancy_name}}` и `{{employer_name}}`.
- **Dry-run по умолчанию**: без флага `--send` ничего не отправляется.
- **История и статистика** в SQLite, дедупликация по `vacancy_id`, дневной лимит.
- **Диагностика селекторов** (`doctor`): показывает, какие элементы hh.ru не найдены после изменения вёрстки.

## Принципы

- **Только ручной вход.** Приложение не запрашивает и не хранит логин и пароль. Сессия хранится в профиле браузера (`.browser-profile/`).
- **Капчу и антибот не обходим.** При проверке процесс встаёт на паузу и ждёт человека.
- **Поведение как у человека:** видимый браузер, случайные паузы, одна вкладка.
- **Лучше остановиться, чем продолжать:** при лимите, блокировке или серии ошибок работа прекращается.
- **Вопросы работодателя не заполняются автоматически.** Такие вакансии пропускаются (`needs_questions`).

## Стек

Node.js 20+, TypeScript (strict), Playwright, zod, better-sqlite3, yaml, commander, pino, vitest.

## Установка

```bash
git clone <URL-репозитория>
cd hh-autoapply
npm install
npx playwright install chromium
```

Создайте личный конфиг:

```bash
# macOS / Linux
cp config.example.yaml config.yaml

# Windows PowerShell
Copy-Item config.example.yaml config.yaml
```

`config.yaml`, `.browser-profile/` и база SQLite добавлены в `.gitignore`: там личные данные и сессия.

## Быстрый старт

```bash
npm run login      # войти на hh.ru вручную, затем закрыть окно
npm run check      # проверить сессию и найти резюме
npm run doctor     # проверить селекторы на реальных страницах
npm run search     # посмотреть, какие вакансии найдутся
npm run apply -- --limit 3                 # DRY-RUN, ничего не отправляется
npm run apply -- --send --limit 1 --resume "Название резюме"   # реальная отправка
npm run stats      # статистика
```

Рекомендуемый порядок: сначала `doctor`, затем `search`, затем dry-run, и только потом `--send` с лимитом 1.

## Команды

| Команда  | Что делает                                                        |
| -------- | ----------------------------------------------------------------- |
| `login`  | Открывает браузер для ручного входа, сохраняет сессию             |
| `check`  | Проверяет, что сессия активна, и выводит названия резюме          |
| `doctor` | Проверяет селекторы на страницах поиска, вакансии и формы отклика |
| `search` | Собирает вакансии, применяет фильтры, выводит таблицу             |
| `apply`  | Откликается на вакансии. По умолчанию dry-run                     |
| `stats`  | Статистика за сегодня, неделю и всё время                         |

### Параметры `apply`

- `--send` — реально отправлять отклики (без флага работает dry-run).
- `--limit N` — ограничить запуск. Итоговый лимит: `min(N, daily_limit, 100)`.
- `--resume "Название"` — выбрать резюме по названию. Параметр отвечает только за резюме, шаблон письма выбирается отдельно по названию вакансии.

## Конфигурация

Конфиг валидируется через zod. Пример: [`config.example.yaml`](config.example.yaml).

```yaml
search:
  queries: ['Fullstack разработчик', 'Frontend разработчик React']
  area: 113
  schedule: remote
  experience: between3And6
  period: 10
  max_pages_per_query: 3

filters:
  title_stop_words: ['Senior', 'Lead', 'QA', 'PHP', 'Java']
  requirements_stop_words: ['Java', 'PHP', 'C#', '.NET']
  requirements_stop_min_hits: 2
  must_have_any: ['React', 'Vue', 'TypeScript', 'Node', 'Fullstack']

limits:
  daily_limit: 10 # жёсткий максимум в приложении — 100
  delay_ms_min: 15000
  delay_ms_max: 45000

cover_letter:
  templates:
    frontend: |
      Добрый день!
      Заинтересовала вакансия «{{vacancy_name}}» в компании «{{employer_name}}». ...
    fullstack: |
      ...
```

Замечания:

- Название вакансии подставляется как есть и не склоняется, поэтому в шаблоне его лучше брать в кавычки: `«{{vacancy_name}}»`.
- Ссылки в письме пишите простым текстом (`https://...`), hh не отображает markdown.
- Шаблон выбирается по названию вакансии: если есть `fullstack`/`full-stack`, `Node` или `Nest`, используется fullstack, иначе frontend.

## Архитектура

```text
src/
  cli.ts                 команды (commander)
  config/                загрузка YAML + схема zod
  browser/
    session.ts           persistent context, ручной вход
    humanize.ts          паузы и прокрутка
    guards.ts            детект капчи, лимитов, блокировок
  hh/
    selectors.ts         все селекторы и тексты-индикаторы
    url.ts               построение URL поиска
    search.ts            сбор и парсинг выдачи
    vacancy.ts           карточка вакансии
    responseForm.ts      форма отклика, резюме, письмо
    applyFlow.ts         сценарий отклика и остановки
    doctor.ts            диагностика селекторов
  core/
    filter.ts            чистые функции фильтрации
    template.ts          выбор и рендер шаблона
    limits.ts            дневные лимиты
  db/                    SQLite и репозиторий
  utils/                 logger, sleep, retry
tests/                   vitest + HTML-фикстуры
```

## Принятые решения

1. **Persistent context вместо логина через форму.** Пароль не хранится, а SMS и капчу проходит человек.
2. **Все селекторы в одном файле.** Вёрстка hh.ru меняется, и править нужно одно место, а `doctor` показывает, что сломалось.
3. **Приоритет `data-qa`, затем role/text.** Сгенерированные CSS-классы нестабильны.
4. **Фильтр — чистая функция.** Он не знает про Playwright и SQLite, поэтому легко тестируется на строках и HTML-фикстурах.
5. **Стоп-слова проверяются раздельно:** по названию и по разделу требований с порогом срабатывания. Проверка по всему тексту давала ложные срабатывания (стек проекта, состав команды).
6. **Дедупликация на уровне БД.** `vacancy_id` — первичный ключ, повторный запуск не создаёт дубликатов и не понижает статус `sent`.
7. **Нет повторных попыток отправки.** Повторное нажатие «Отправить» опаснее ошибки. Ретраи есть только у навигации.
8. **Неполная страница выдачи считается последней**, чтобы не ждать таймаут на несуществующей странице.

## Риски и ограничения

- Автоматизация откликов может нарушать правила hh.ru. Возможны ограничение или блокировка аккаунта.
- Начинайте с малых лимитов (1–5 откликов), не запускайте часто, не используйте несколько аккаунтов.
- Приложение не обходит капчу и антибот и останавливается при признаках лимита или блокировки.
- Вёрстка hh.ru может измениться в любой момент, тогда понадобится обновить `selectors.ts` (поможет `doctor`).
- Часть селекторов формы отклика зависит от аккаунта и сценария. Проверяйте результат вручную в разделе «Отклики».
- Массовые шаблонные отклики дают слабый результат. Персонализируйте письма и используйте фильтры.
- Проект не рассчитан на нетехнических пользователей и не является коммерческим продуктом.

## Если что-то не работает

| Проблема                   | Что делать                                              |
| -------------------------- | ------------------------------------------------------- |
| Не найден конфиг           | Скопируйте `config.example.yaml` в `config.yaml`        |
| `Executable doesn't exist` | `npx playwright install chromium`                       |
| Профиль занят              | Закройте другие окна браузера приложения                |
| Сессия не активна          | `npm run login`                                         |
| Селектор не найден         | `npm run doctor`, затем обновите `selectors.ts`         |
| Ошибка валидации конфига   | Прочитайте путь к полю в сообщении и исправьте значение |
| Капча                      | Решите её вручную в открытом окне                       |
